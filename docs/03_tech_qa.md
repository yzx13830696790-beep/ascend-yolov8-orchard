# 技术问答：三层追问脚本

每个技术点都准备"是什么 → 为什么这么选 → 不这么选会怎样"三层。被追问到第三层还能
给出机制和数字，才是真正掌握了这个取舍，而不是"跑通过"。

## 1. 剥离 NMS

- 是什么：ONNX 只导主干，NMS 放到 Host 侧 C++。
- 为什么：ATC 对 NonMaxSuppression 支持差、动态 shape 不友好；后处理放 Host
  更灵活，能对 8400 候选框做独立调优。
- 不这么选会怎样：强行转会把算子拆成多个小算子，时延翻倍且精度不可控。

## 2. PTQ vs QAT

- 是什么：先 PTQ 再按需 QAT。
- 为什么：QAT 要重训、周期长；PTQ 在检测上通常掉 1~3pt，配合混合精度可控。
- 不这么选会怎样：直接 QAT 浪费两周，且没有 PTQ 基线就说不清"混合精度救了多少"。

## 3. 混合精度

- 是什么：敏感层（检测头回归分支、backbone 浅层）保 FP16，其余 INT8。
- 为什么：掉点集中在这两类层，逐层敏感度分析能定位。
- 不这么选会怎样：全局 INT8 掉 2.4pt 超约束；全 FP16 多花 4ms。

## 4. 三线程流水

- 是什么：取帧 / 预处理+推理 / 后处理三线程并行 + 双 buffer。
- 为什么：单线程时 Device 在等 Host，利用率不到 40%。
- 不这么选会怎样：端到端等于三段串行相加，浪费 8~10ms。

## 5. Device 常驻内存

- 是什么：输入输出 buffer 只申请一次，不每帧申请。
- 为什么：每帧 H2D/D2H 大块拷贝是隐藏瓶颈。
- 不这么选会怎样：每帧多 2~3ms 且内存碎片化。

## 必背故事模板（现象→定位→根因→动作→数字）

1. **NMS 转不过去**：ATC 报算子不支持 → 查日志确认 NonMaxSuppression → 剥离后处理
   重导 → C++ 向量化 NMS → 后处理 3.2ms 降到 0.9ms。
2. **AIPP 色域错配**：OM mAP 0.86→0.74 → 逐层 dump 发现第一层 cosine 0.94 层层放大
   → 定位 DVPP 用 BT.601 而训练用 BT.709 → 对齐 csc → 回到 -0.6pt。
3. **归一化系数错**：mean/var 忘乘 255 → 框系统性偏移、置信度偏低 → 单图对比 AIPP
   前后张量均值方差定位 → 修正恢复。
4. **拷贝成瓶颈**：msprof 显示推理 9ms、端到端 18ms → 定位每帧两次大块拷贝 → Device
   常驻 + 双 buffer → 端到端降 6ms。
5. **量化敏感层**：全局 INT8 掉 2.4pt，单层敏感度发现 reg 分支 conv 掉 1.8pt → 该层
   保 FP16 → 多 0.4ms、收回 1.6pt。

## 一个"没做成"的故事

"我试过剪枝把时延再压 2ms，但剪完 mAP 掉 1.5pt，微调 20 epoch 只收回 0.7，不划算
就放弃了，改走蒸馏 + 混合精度。"——诚实 + 量化取舍，比十个成功故事更可信。
